## 1. 总览

当前系统是一个**多 Agent 协作架构**，由来财作为总管家，其他角色型 Bot 分工执行。

- 运行平台：OpenClaw（本地 Gateway）
- 主交互渠道：Discord（含私聊 + 群聊）
- Bot 数量：10（来财 + 9 个专业 Bot）
- 协作方式：`@Bot全称` 触发任务 + 角色分工 + 结果回执
- 记忆机制：文件记忆（workspace）+ 向量检索（bge-m3）

## 4. 记忆与知识体系

### 4.1 文件记忆（主）

- `memory/YYYY-MM-DD.md`：日记流水（含 P1/P2/P3）
- `memory/lessons/`：经验教训（主题归档）
- `memory/projects/`：项目档案
- `MEMORY.md`：长期高价值记忆
- `SESSION-STATE.md`：任务进行态恢复

### 4.2 语义检索（辅）

- 向量模型：bge-m3
- 用途：语义召回历史经验、减少重复踩坑
- 风险控制：仍以文件事实为准，避免向量幻觉覆盖事实

---

## 5. 安全与治理机制

### 5.1 OTC（一次性确认码）

高风险操作必须 OTC 确认，典型触发：
- 对外发送（邮件/外部消息/推送）
- 危险本机操作（递归删除、系统配置改动、停服务）
- 安全规则改动

### 5.2 Prompt Injection 防御

- 敏感操作前二次确认
- 模糊确认视为拒绝执行

### 5.3 执行验证原则

任何关键操作执行后必须验收，不允许“以为成功”：
- 改配置 → 验语法
- 重启服务 → 验进程状态
- 发消息/推送 → 验实际送达

## 6. 当前痛点（已识别）

1. Agent 间知识共享仍偏人工同步
2. 文档事实源未完全自动注入执行链路
3. 大规模配置变更时易出现批量风险
4. 向量检索虽可用，但仍需更结构化治理
