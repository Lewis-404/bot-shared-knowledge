# Bot 记忆系统规范 v1.0

> 所有 bot 统一执行的记忆管理规则。确保跨 session、跨 compaction 的信息持久化。

## 1. 三层记忆架构

```
memory/
  INDEX.md          ← 总索引（启动时第一个读的文件）
  YYYY-MM-DD.md     ← 每日日记（事件流水，实时追加）
  lessons/          ← 经验教训（按主题归档，同一主题追加到同一文件）
  decisions/        ← 决策记录
  projects/         ← 项目档案
  people/           ← 人物档案
MEMORY.md           ← 长期精华（跨场景通用智慧，极少更新）
```

### 不混用原则

| 层级 | 用途 | 更新频率 |
|------|------|----------|
| 日记 `YYYY-MM-DD.md` | 所有细节（决策、完成、踩坑） | 实时追加 |
| `lessons/` | 按主题组织教训，不按时间 | 有教训时追加 |
| `MEMORY.md` | 跨场景通用智慧 | 一天最多更新一次 |

## 2. WAL 协议（Write-Ahead Log）

**核心原则：先写记忆，再回复。**

万一 session 挂了、compaction 了，记忆不会丢。

### 触发条件

以下情况必须先写 memory 再回复用户：
- 主人表达偏好
- 做出决定
- 给出截止日期
- 纠正 bot 的错误

### 流程

```
事件发生 → 写入 memory 文件 → 回复主人
```

**不是**：
```
事件发生 → 回复主人 → （忘了写 memory）
```

## 3. 写入规范

- **追加用 `printf >>`**，永远不会覆盖，不依赖 Edit 精确匹配
- **只在文件不存在时用 Write**
- 没内容就不写，不写"系统空闲，无变化"这种废话
- 教训追加到已有的主题文件，不要每个教训建一个新文件
- 3-10 行，有细节但不啰嗦
- **新建文件后更新 INDEX.md**

### 日记格式

```markdown
## HH:MM — [简述] [P1/P2/P3]
- 关键内容
- 更多细节
```

## 4. 重要性标记（P1/P2/P3）

写入日记时，在条目末尾标注重要性等级：

| 等级 | 含义 | 示例 |
|------|------|------|
| `[P1]` | 主人的决策、偏好、截止日期、重大事件 | `确认副业方向为 AI 教程` |
| `[P2]` | 技术方案、架构变更、教训总结 | `完成代码审查，发现3个安全问题` |
| `[P3]` | 日常操作、常规任务完成（默认，可省略） | `Heartbeat 检查，一切正常` |

**检索和反思时优先处理 P1 > P2 > P3。**

## 5. 记忆持久化（防 Compaction 丢失）

### L1：增量写入（对话过程中）

以下情况发生时，**立即**写入 `memory/YYYY-MM-DD.md`，不要攒到后面：

- 做出了技术决策（选型、方案确定、取舍）
- 完成了一个阶段性步骤（接口写完、测试通过、bug 定位到）
- 发现了关键信息（报错原因、环境差异、配置细节）
- 收到了明确的需求变更
- 产出了需要复用的代码片段或配置

P1 级别的决策**同时更新 MEMORY.md**。

### L1.5：SESSION-STATE.md 持续维护

当任务有明确的多步骤流程时，维护 `SESSION-STATE.md`：

- **任务开始时**创建/更新，记录目标和计划
- **每完成一个步骤**后更新进度和下一步
- **遇到阻塞**时记录阻塞项
- **任务结束时必须清空**对应段落
- **超过 24 小时未更新的条目视为过期**

SESSION-STATE.md 是 checkpoint，不是日志。只保留**当前状态**，不堆积历史。

### L4：幂等恢复流程

每次 session 开始时：

1. 读 `SESSION-STATE.md` → 恢复「我在做什么、做到哪了」
2. **24h 过期检查**：超过 24h 未更新的条目 → 标记 `⚠️ 疑似过期`，向主人确认
3. 读 `memory/YYYY-MM-DD.md`（今天） → 恢复「今天发生了什么」
4. 如果 SESSION-STATE 中有涉及文件列表 → 读取关键文件恢复技术上下文
5. 恢复后在当日日记记录：`## HH:MM — 上下文恢复 [P3]`

**这个流程是幂等的**——无论是 compaction 后、/new 后、还是跨天 session reset，执行逻辑一样。

## 6. INDEX.md 维护

- `memory/INDEX.md` 是记忆系统的总索引
- **写入日记或 lessons 后，顺手更新 INDEX.md**
- 增量维护即可，不需要专门的定时任务

## 7. MEMORY.md 安全规则

- **ONLY load in main session**（直接与主人的对话）
- **DO NOT load in shared contexts**（群聊、其他人的 session）
- 只放跨场景通用精华

## 8. 记忆衰减与清理

每周一次检查（heartbeat 时执行）：

| 等级 | 超时 | 处理 |
|------|------|------|
| P3 | >14 天且未被引用 | 可删除 |
| P2 | >30 天 | 检查是否已提炼到 lessons/，是则可删 |
| P1 | 永不 | 只能主人授权删除 |

## 9. 反思机制

每 3 天一次：

1. 读取最近 3 天的日记
2. 从琐碎事件中提炼高层洞察（模式、规律、趋势）
3. 洞察写入 `memory/lessons/` 对应主题文件或 `MEMORY.md`

**反思的目标：数据 → 认知。** 不是复制日记，是发现"为什么"和"下次怎么做"。

## 10. Session 启动时间感知

每次 session 启动时，**必须第一步获取时间基准**：

```bash
date +"%A, %Y-%m-%d"
TODAY=$(date +%Y-%m-%d)
YESTERDAY=$(date -v-1d +%Y-%m-%d)
```

汇报时使用明确时间词：
- ✅ "今天上午你做了 X"
- ✅ "昨天你完成了 Y"
- ❌ "你完成了 X"（模糊）

**在说"今天"或"昨天"之前，先对比文件名和当前日期。**

## 11. AGENTS.md 中的完整规则模板

将以下内容放在 AGENTS.md 的 `## 记忆系统` 段落中（替换旧的 `## Memory` 段落），确保与 `## Safety` 或 `## 安全规则` 段落之间没有其他记忆相关的重复段落。

同时检查并删除以下可能散落在 AGENTS.md 其他位置的重复段落：
- `## 📝 记忆持久化规则（防 Compaction 丢失）`
- `## Session 启动时间感知（强制规则）`
- `## Session 启动时间感知（强制执行）`
- `**每次 session 启动时必须明确当前时间**` 独立段落
