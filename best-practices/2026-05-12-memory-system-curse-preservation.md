## 编译真理

### 1. 「记忆诅咒」实验室实证

omarsar0 发表大规模实验结论：

- **实验规模**：7 个 LLM × 4 种游戏 × 500 轮
- **核心发现**：长上下文让 Agent **越来越保守**、**爱翻旧账**
- **Forward-looking 意图被侵蚀**：Agent 倾向于重复历史模式而非探索新策略
- **CoT 放大退化**：Chain-of-Thought 推理在长上下文中反而加剧保守倾向
- **缓解方案**：LoRA 适配器 + 记忆消毒

**关键洞察**：这不是推理能力退化，是**策略多样性**退化。Agent 不是变笨了，是变得不敢尝试新东西了。

**可落地点**：
- Hermes Agent session 历史需定期重构叙事方向，避免累积「翻旧账」模式
- 考虑对记忆做前瞻性过滤而非简单截断

### 2. 头尾保留策略：工业界三方收敛

Arize AI 和 AI Engineer 同日提出相同方案——**头尾保留 + 中间卸载到向量检索**：

```
[Head: 最近活跃上下文] ... [向量检索: 中间历史] ... [Tail: 任务锚点]
```

- **Head 保留**：最近 N 轮对话，保证当前任务连贯性
- **Tail 保留**：任务初始目标和约束，防止漂移
- **中间卸载**：历史中间段卸载到可检索向量库，按需召回
- **截断和摘要均失败**：简单截断丢关键信息，摘要丢失细节

**子 Agent 拆分策略**：重上下文场景用子 Agent 拆分管理，每个子 Agent 只持有相关片段。

**可落地点**：
- Hermes + bge-m3 记忆系统加入头尾保留策略
- 中间段卸载到 bot-shared-knowledge 向量检索
- cron Agent 执行记录采用头尾保留策略，中间摘要入 bge-m3 向量库

### 3. 当日核心收敛

三条情报（1 学术 + 2 工业）独立指向同一方向：
- 长上下文不是越多越好——**信息密度 > 信息量**
- 记忆管理的核心不是「存多少」而是「何时检索什么」
- 前瞻性过滤（memory sanitization）比上下文截断更有价值
